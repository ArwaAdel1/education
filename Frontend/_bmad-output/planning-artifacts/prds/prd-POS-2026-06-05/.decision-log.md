# Decision Log — Teacher AI Academy PRD

## 2026-06-05

| # | Decision | Rationale | Source |
|---|---|---|---|
| D-1 | Journey-led PRD structure chosen over capability-first | Three distinct user types (student, teacher, support) with very different flows; journeys expose UX gaps early | Coaching session with Maro |
| D-2 | MVP scope: 9 features (Auth, Profiles, Content Mgmt, AI Quiz Gen, Teacher Dashboard, Enrollment & Payment, Student Dashboard, AI Student Chat, Support Flow) | User confirmed clean MVP cut; AI features (quiz gen + chat) are key differentiators and included in v1 | Maro's explicit call |
| D-3 | Payment model: dual path — Paymob (self-serve) + promo codes (assisted) | Egyptian students use diverse payment methods; Vodafone Cash/InstaPay are common among teens without cards | Business model discussion |
| D-4 | Content model: Stage → Chapter → Lesson (YouTube + PDFs) | Simple, familiar hierarchy; no extra fields beyond core | User confirmation |
| D-5 | Lifetime access model: student who pays for a month keeps it forever | Core business model decision from user; accounting implications noted | User input |
| D-6 | Single-tenant architecture (one teacher per instance) | Simplified data model, no isolation overhead, aligns with single-teacher product model | User revision |
| D-7 | Gemini (Google) as LLM for both AI Tutor and Quiz Generator | Strong Arabic support, competitive pricing; confirmed by user | User input |
| D-8 | YouTube unlisted embedding for video delivery | Free, scalable; teacher manages their own YouTube channel | User input |
| D-9 | Web-only (responsive) for MVP; no native apps | Egyptian students primarily use mobile browsers; native apps deferred to v3 | User input |
| D-10 | Bilingual AR/EN UI + content support | Egyptian market requires both languages; confirmed by user | User input |
| D-11 | Removed FR-9 (Scheduled Content Release) | Teacher wants content to be available immediately upon publish, not tied to schedules | User revision |
| D-12 | Removed quiz status tracking from FR-20 | Student should not see "not started / in progress / completed" labels; only score on completed quizzes | User revision |
| D-13 | Enrollment unit is **chapter**, not stage | Student buys individual chapters a la carte; lifetime access per chapter | User clarification |
| D-14 | Student Dashboard has two views: "My Courses" and "All Content" | My Courses shows purchased chapters; All Content shows full tree with locked/unlocked distinction | User clarification |
| D-15 | RAG chunking: paragraph-level | Simple, works well for study material PDFs | User decision |
| D-16 | AI Tutor cost control: per-student daily query cap | Prevents runaway costs while keeping it usable | User decision |
| D-17 | AI Quiz Generator reuses the same RAG pipeline as AI Tutor | Single embedding pipeline serves both features; teacher's content is indexed once, queried by both | User decision |
| D-18 | Paymob integration: Iframe / Hosted Checkout | Simplest PCI-compliant approach; sufficient for one-time payment flow | User decision |
| D-19 | Promo codes scoped to a specific chapter | Support agent selects which chapter the code unlocks | User decision |
| D-19a | **OVERRIDE:** Promo codes are now universal (any course) | Changed from chapter-specific to universal — student can apply the code to any chapter they choose | User revision |
| D-20 | PDF storage: AWS S3 with pre-signed URLs | Server verifies enrollment, returns 60-min S3 URL; scalable and secure | User decision |
| D-21 | Deployment: AWS Elastic Beanstalk + RDS PostgreSQL | Simple deploy from GitHub, managed infrastructure, easy to start | User decision |
| D-22 | Written Architecture Decision Record (ADR) at `architecture.md` | Captures all 20+ decisions with data model, API modules, RAG pipeline, payment flow, and deployment | Winston |
| D-23 | Background jobs: synchronous for MVP | PDFs at MVP scale are small; no Redis/queue needed yet | User decision |
| D-24 | Monitoring: CloudWatch + Sentry free tier | CloudWatch for infra logs, Sentry for error tracking | User decision |
| D-25 | Rate limiting: 100 req/min per IP via express-rate-limit | Prevents abuse with minimal overhead | User decision |
| D-26 | PDF text extraction: pdf-parse | Free, sufficient for born-digital PDFs; Textract in v2 if needed | User decision |
